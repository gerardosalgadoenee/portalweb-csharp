Lenguaje de Programación C#

Un lenguaje moderno, versátil y potente

Origen

C# fue desarrollado por Microsoft a finales de los años 90 como parte de su iniciativa .NET. Su diseño inicial se inspiró en lenguajes como C++ y Java, buscando combinar la potencia del primero con la simplicidad del segundo.

Creador: Anders Hejlsberg

Ingeniero de Software Danés - Arquitecto Principal de C#

Trayectoria: Anders Hejlsberg es uno de los arquitectos de software más influyentes de la historia moderna. Antes de unirse a Microsoft en 1996, diseñó Turbo Pascal (1983) en Borland, que revolucionó la programación en PC, y posteriormente Delphi (1995), un entorno de desarrollo visual pionero. Su experiencia en compiladores y lenguajes de tipado fuerte sentó las bases para el diseño de C#.

En Microsoft: En enero de 1999, Hejlsberg formó un equipo interno en Microsoft para crear un nuevo lenguaje orientado a objetos inicialmente llamado "COOL" (C-like Object Oriented Language). El equipo incluyó a Scott Wiltamuth y Peter Golde como co-diseñadores. El nombre "COOL" no pudo registrarse por problemas de marca, por lo que en julio de 2000, durante la Professional Developers Conference (PDC), Microsoft anunció oficialmente el lenguaje como C# junto con .NET Framework y Visual Studio .NET.

Legado: Hejlsberg ha sido el arquitecto líder de C# durante más de 25 años, dirigiendo la evolución del lenguaje desde C# 1.0 hasta C# 14. También lideró el desarrollo del compilador Roslyn (open source desde 2014) y el lenguaje TypeScript (2012).

Ejecución y Arquitectura del Lenguaje

C# es un lenguaje de naturaleza híbrida que utiliza una máquina virtual para su ejecución. El proceso se divide en dos etapas principales:

  1. Compilación a código intermedio: Cuando compilas tu proyecto, el código fuente en C# no se convierte directamente en instrucciones que el procesador entienda. En su lugar, se compila a un lenguaje intermedio llamado IL (Intermediate Language) o CIL.
  2. Ejecución en la Máquina Virtual: Este código IL es procesado por el CLR (Common Language Runtime), que actúa como la máquina virtual de .NET. Dentro del CLR, un compilador JIT (Just-In-Time) traduce el código intermedio a código de máquina real (ceros y unos) justo en el momento en que la aplicación se ejecuta en el sistema operativo.

Principales Usos

  • Desarrollo de aplicaciones de escritorio (Windows Forms, WPF).
  • Desarrollo web robusto (ASP.NET Core).
  • Creación de videojuegos utilizando el motor Unity.
  • Aplicaciones móviles multiplataforma (MAUI).
  • Servicios en la nube y microservicios.

Versión Utilizada

Actualmente se trabaja con la versión estable más reciente (C# 14 junto con .NET 10), la cual incluye mejoras en colecciones, extensiones de partial members, nuevos atributos de resolución de sobrecarga y la clase Lock para sincronización de hilos.

Hitos Históricos de C#

1999

El Proyecto COOL: Inicia el desarrollo de un nuevo lenguaje moderno, con tipado fuerte que se integraría perfectamente con la nueva plataforma .NET.

2002

C# 1.0 Lanzamiento Oficial: Debut oficial junto a .NET Framework 1.0. Incluía clases, interfaces, propiedades y eventos.

2005 - 2007

Evolución Técnica (2.0 y 3.0): Introducción de Generics, soporte principal de Unity para videojuegos, expresiones Lambda y la llegada revolucionaria de LINQ.

2014

Era Open Source: Microsoft libera el compilador Roslyn en GitHub y comienza el desarrollo multiplataforma con .NET Core.

2020

Unificación Total: Lanzamiento de .NET 5, unificando definitivamente el Framework clásico, Core y Mono en un único ecosistema global.

Arquitectura de Ejecución: ¿Por qué C# es Híbrido?

A menudo surge la duda de si C# es compilado o interpretado. La realidad es que es un lenguaje híbrido que combina lo mejor de ambos mundos mediante el uso de una máquina virtual. A continuación se explica a detalle el porqué de esta infraestructura:

1. La Fase Compilada (Tiempo de Desarrollo)

C# no se traduce directamente a código que el procesador nativo de tu computadora entienda (como ceros y unos de Intel o AMD). En su lugar, el compilador de C# (Roslyn) traduce tu código fuente a un lenguaje intermedio de alto nivel llamado IL (Intermediate Language) o CIL.

Salida: Archivos .dll o .exe en código IL

2. El Rol de la Máquina Virtual (Tiempo de Ejecución)

Para ejecutar ese código intermedio se requiere del CLR (Common Language Runtime), que funciona como la máquina virtual de .NET. El CLR es el corazón del sistema: administra la memoria (Garbage Collector), gestiona la seguridad y aísla la aplicación del sistema operativo físico.

Entorno: CLR (Common Language Runtime)

3. La Fase Interpretada/JIT (Just-In-Time)

Aquí es donde ocurre la parte híbrida. En lugar de interpretar el código IL línea por línea (como haría un lenguaje puramente interpretado), un componente dentro del CLR llamado Compilador JIT (Just-In-Time) toma los bloques de código IL y los compila a código de máquina real justo en el momento en que la aplicación los necesita.

Resultado: Velocidad casi nativa

¿Por qué Microsoft diseñó C# de esta manera?

  • Multiplataforma Real: El mismo archivo compilado (.dll) funciona en Windows, Linux o macOS sin cambios; solo necesitas que esa plataforma tenga instalado su respectivo CLR.
  • Optimizaciones sobre la marcha: El compilador JIT puede optimizar el código específicamente para las instrucciones exactas del procesador que está usando el cliente final en ese instante.
